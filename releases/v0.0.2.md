# v0.0.2 — Sharing, in-app updates, Comix restored

**Released 2026-10-10**

Second public beta. This one gets Mangora in front of other people and keeps it up to date: share a
series with a single link, install new versions without leaving the app, plus a rebuilt Comix source
and a reader fix.

## Highlights

- **Share any series.** A share button in the viewer produces a link to the public site that opens the
  exact same series — and, when the app is installed, opens it directly in Mangora. One-shots and
  galleries share too.
- **Links open in the app.** Shared links (App Links) resolve straight to the series, chapter and
  scanlation group instead of the landing page — no menu, no searching.
- **In-app updates.** Settings → About checks for a new release, shows the version and notes, downloads
  the APK and installs it — with a clear prompt if Android still needs the "install unknown apps"
  permission. An optional toggle includes pre-releases for testers.
- **Comix works again.** Comix rebuilt their site and broke the previous bridge; search, manga pages and
  the reader are all working again through a rebuilt bridge.
- **Reader fix.** Fixed a crash ("Unable to activate keep awake") that could fire right after opening a
  chapter, most often on a cold start from a shared link.
- **Safer sharing.** Adult sources (NHentai, Manhwa18) can only be shared once age-restricted sources
  are enabled in Settings, so a shared link never drops someone onto an adult source by surprise.

## Website

- Public landing pages for shared series and one-shot links, with an "Open in app" path and a store
  fallback.
- Publishes the release signing fingerprint at `/.well-known/assetlinks.json` so Android can verify App
  Links.

## Install

ARM64 Android 7.0+ only — 32-bit ARM is not supported.

## Known limitations

- App Links auto-verify on the release build. Debug builds (`expo run`, dev client) are signed with a
  different key, so a shared link may open the landing page instead of the dev app — that is expected.
- Comix downloads need the app in the foreground, because its page URLs depend on the in-app browser
  session.
- Live browse and search feeds are still not cached for offline use; only downloaded chapters read
  offline.
