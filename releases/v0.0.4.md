# v0.0.4 - Auto bubbles, pre-translation, ONNX OCR, and extension management

**Released 2026-10-20**

Fourth public release. The focus is on faster runtime translation, pre-translating downloaded chapters, expanding on-device OCR model support, and finishing the extension lifecycle.

## Highlights

- **Auto bubbles.** A new AI-only translation mode that starts producing overlays before a page finishes OCR. Each bubble is emitted as soon as its OCR regions are ready, then 1-5 bubbles (default 3) are sent in one Gemini request. Previously OCRed pages are attached as context so names and tone stay consistent. Batching keeps API usage bounded while reducing time-to-first-translation. The buffer flushes at the configured batch size, when OCR goes idle, or after 900 ms without a new bubble. The existing automatic mode was renamed from **Auto** to **Auto pages** and keeps its original full-page behavior.
- **Translation controls and live telemetry.** The Translation tab now has a **Bubbles per batch** slider (1-5) under the AI workers, a collapsible **API usage** dropdown with live Gemini RPM/TPM/RPD meters, and a collapsible **Pipeline metrics** table with aligned page-scan, bubble-OCR, translation, page and bubble counters.
- **Duplicate OCR queue fix.** Pages that already had a translation state could be re-enqueued while scrolling, causing already-YOLOed pages to be scanned again and flooding the bubble OCR queue. Page enqueueing now skips any URL that already has state, and completed RAM OCR records are reused when a run restarts instead of running detection again.
- **Pre-translation queue.** Queue whole downloaded chapters for batch OCR + translation under **Settings > Translation queue**. Each page runs the same YOLO -> OCR -> free/AI translation pipeline as the reader, then is written to the translation cache so opening the chapter feels instant. The queue runs one page at a time, pauses when the app leaves the foreground, and persists as JSON so a restart does not lose progress. A foreground notification shows per-page progress, and the reader retry button still handles any pages that failed.
- **ONNX Runtime OCR engine.** OCR now runs through `onnxruntime-react-native` instead of the prior ExecuTorch path. The old ExecuTorch model files and glue code were removed.
- **PP-OCRv5 Korean model.** A second downloadable on-device OCR model is available: **PP-OCRv5 Korean** for Korean and Latin scripts (13 MB). It joins **Baberu OCR** (Japanese, Chinese, English). The model you need is chosen automatically from the chapter language. Download either pack from **Settings > OCR models**. The settings screen now has dedicated sections for OCR models and the translation queue with download, cancel and delete controls, byte-accurate progress, and `.part` file promotion so an interrupted download never looks installed.
- **Extension uninstall.** Installed extensions can now be uninstalled directly from the app. The extension source page gained an **Uninstall** action, and Mangora requests `REQUEST_DELETE_PACKAGES` so Android handles the removal. The source list and manga cards reflect removal immediately.
- **Extension filter refactor.** The source filter sheet was rewritten to match Mihon's filter schema. Filter groups, select, sort, text and checkbox controls all render with proper defaults, validation, and summary chips. Filter state is serialized to a schema string and patches, so the reader applies the same filters to every request for that source.
- **Translation pipeline refactor.** The in-reader translation flow was reworked: the old `TranslationStatusChip` component was replaced with `PageTrStatusBadge`, the reader translation hook was expanded to handle cached pre-translated pages and partial failures, and a runtime lock prevents the reader and the pre-translation queue from running OCR/inference at the same time. See `TR_pipeline.md` for the full file/function map and invariants.
- **Serverless by design.** Mangora operates no application backend, account service or central sync database. Library data, history, settings, OCR models, translation cache and Gemini usage counters stay on the device. Optional online features send requests directly from the device to the third-party service involved.

## Install

ARM64 Android 7.0+ only - 32-bit ARM is not supported.

## Known limitations

- Pre-translation processes one page at a time and serializes OCR, so large chapters take a while. The queue pauses when the app is backgrounded and resumes when you return.
- Auto bubbles with a batch size of 1 shows each bubble as soon as possible but makes more Gemini requests. Raise **Bubbles per batch** to reduce request volume.
- ONNX Runtime model loading is lazy; the first page you translate after a model download may take a few extra seconds to initialize the session.
- Extension compatibility depends on the host API. Extensions built for Mihon source API 1.7+ may fail until the host is updated.
