# v0.0.5 - Parallel OCR engines, PP-OCR line detection, and queue resume fixes

**Released 2026-10-20**

Fifth public release. On-device OCR now uses real parallel inference, PP-OCRv5
reads individual text lines, and pre-translation survives pause/resume without
duplicating progress or notifications.

## Highlights

- **Parallel Baberu OCR (engine pool).** The bubble-worker slider now controls real parallel inference instead of a queue in front of one locked ONNX session. Every Baberu worker owns an independent engine set (vision + decoder sessions), so 3 workers can run 3 recognitions at once. The slider ranges 1-5 (default 3) and shows the effective RAM estimate: about 121 MB per worker, so 3 uses roughly 363 MB. Slots are created lazily, idle slots survive a worker-count reduction, and all sessions are released when the reader closes.
- **PP-OCRv5 line detection.** The PP-OCRv5 Korean/Latin pack now includes the PP-OCRv5 DBNet text-line detector alongside the CTC recognizer (~18 MB total). DBNet finds the individual lines inside each YOLO bubble, each line is cropped to the recognizer's 48 px input, and the results are joined into one bubble string. This replaces whole-bubble recognition, which squashed multiple lines into one tensor and produced noisy output.
- **PP-OCR stays single-worker.** PP-OCR needs its detector and recognizer together, so its bubble-worker slider is locked at 1 until its throughput has been measured on device. The reader explains this below the slider.
- **Pre-translation bubble workers.** Pre-translate now has its own **Bubble workers** slider (1-5, default 5) for Baberu, so several bubbles inside one page are OCRed concurrently instead of one at a time. PP-OCR jobs are clamped to 1. The pre-translate settings sheet now scrolls as one body.
- **Resume-safe pre-translation.** Paused jobs persist a `nextPageIndex` and resume from the first unprocessed page instead of replaying page 0. Resumed jobs no longer re-count already cached pages, so a job paused at 110/200 resumes at 110/200 rather than jumping to 220/200. AI context is restored from the translation cache without re-counting those pages.
- **No notification flood on resume.** Cached pages do not emit progress notifications, and progress updates are coalesced into one live notification so a burst of updates replaces the previous notification instead of stacking them.
- **Queue counter guards.** The queue row clamps displayed progress to the chapter length, protecting the UI from stale or migrated job records.

## Install

ARM64 Android 7.0+ only - 32-bit ARM is not supported.

## Known limitations

- Each Baberu worker keeps its own engine set in RAM (~121 MB). The default of 3 is roughly 363 MB; use 1-2 workers on 4 GB devices.
- PP-OCRv5 Korean/Latin runs its DBNet detector and recognizer on one worker. Concurrency will be reconsidered after on-device timing.
- Pre-translation still processes one page at a time; bubble workers only parallelize recognition inside the current page.
- Auto bubbles with a batch size of 1 shows each bubble as soon as possible but makes more Gemini requests. Raise **Bubbles per batch** to reduce request volume.
- ONNX Runtime model loading is lazy; the first page you translate after a model download may take a few extra seconds to initialize the session.
- Extension compatibility depends on the host API. Extensions built for Mihon source API 1.7+ may fail until the host is updated.
